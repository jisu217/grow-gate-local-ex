# AI Agent 호출 흐름

> 마이페이지 "AI 진단 다시 실행" 버튼 → 결과 표시까지의 데이터 흐름
> 작성: 혜원 / 2026-06-21

---

## 1. 전체 흐름 한눈에

```
[마이페이지]
  "AI 진단 다시 실행" 클릭
        │
        ▼
  ① 진단 대상 선택 (제품 선택 or 직접 입력)
        │
        ▼
  ② POST /api/diagnosis  ← 요청 JSON 전송
        │
        ▼
  [백엔드] diagnosis_runs 생성 (status: pending)
        │  knowledge_snapshot 복사 (제품 기반일 때)
        ▼
  ③ 비동기 AI Agent 처리 (pending → running → done)
        │
        ▼
  ④ GET /api/diagnosis/{run_id} 폴링 또는 알림
        │
        ▼
  ⑤ 마이페이지 "최근 진단 카드" 갱신 + 결과 표시
```

---

## 2. 버튼 클릭 시 넘어가는 데이터 (요청 JSON)

### 케이스 A — 저장된 제품 기반 재진단
```json
{
  "product_id": "prod_001",
  "company_id": "comp_001",
  "hs_code": "850760",
  "target_country": "Germany",
  "knowledge_snapshot_id": "snap_001"
}
```
- `product_id`가 있으면 백엔드가 해당 제품의 `product_knowledge`를
  진단 시점 스냅샷(`knowledge_snapshot`)으로 복사 → 진단 입력으로 사용.

### 케이스 B — 직접 입력 진단 (제품 미등록)
```json
{
  "product_id": null,
  "company_id": "comp_001",
  "input_data": {
    "product_name": "리튬이온 배터리팩",
    "hs_code": "850760",
    "target_country": "Germany"
  }
}
```
- `product_id`가 없으면 `input_data`에 제품명·HS Code를 담아 전송
  (ERD의 `diagnosis_runs.input_data` 컬럼에 대응).

> 마이페이지에서는 보통 **케이스 A**(이미 등록한 제품을 다시 진단)가 주 시나리오.

---

## 3. 처리 상태 (status 전이)

| 상태 | 의미 | 마이페이지 표시 |
| :--- | :--- | :--- |
| `pending` | 요청 접수, 대기 | "진단 준비 중..." |
| `running` | AI Agent 분석 중 | 진행률/스피너 |
| `done` | 완료 | 점수·요약 카드 표시 |
| `failed` | 실패 | "다시 시도" 버튼 |

> 결과 수신 방식: **폴링**(2~3초 간격 `GET /api/diagnosis/{run_id}`) 또는
> 추후 WebSocket/SSE로 개선 가능. MVP는 폴링으로 충분.

## 4. 결과가 오면 마이페이지에서 보여줄 항목

진단 응답 `result`(JSON)를 카드로 매핑:

| 결과 항목 | 마이페이지 표현 | 출처 필드(예시) |
| :--- | :--- | :--- |
| 전체 점수 | 도넛/게이지 차트 (예: 72점) | `result.diagnosisScore` |
| 요약 | 한 줄 코멘트 | `result.summary` |
| 규제 위험 | 위험 등급 뱃지(high/med/low) | `result.riskItems` |
| 인증 필요사항 | 체크리스트 | `result.regulations` |
| FTO 위험 | 국가별 위험 표시 | `result.fto` |
| 30·60·90일 로드맵 | "오늘 할 일 카드"로 연결 | `result.actionRoadmap` |
| 근거/출처 | "근거 보기" 링크 | `result.sources` |

### 응답 예시 (백엔드 현재 반환 형태 기반)
```json
{
  "id": "diag_017",
  "status": "done",
  "result": {
    "diagnosisScore": 72,
    "summary": "전반적인 수출 준비도는 양호하나 FTO 리스크 보완 필요",
    "riskItems": [
      { "level": "high", "label": "FTO 리스크 보완 필요" },
      { "level": "medium", "label": "인증서 만료 임박 항목 있음" }
    ],
    "actionRoadmap": { "d30": 4, "d60": 4, "d90": 4 },
    "evidenceSources": ["관세청", "KOTRA", "KTL", "SafetyKorea", "KIPRIS"]
  }
}
```

## 5. 사용자 경험(UX) 포인트

- **재진단 전 확인 모달**: "제품 지식이 마지막 진단 이후 수정되었습니다. 최신 데이터로 다시 진단할까요?" → 데이터 변경 시에만 노출.
- **이전 진단과 비교**: 재진단 후 점수 변화(▲/▼)를 보여주면 "개선됐다"는 효능감 제공.
- **진단 중 이탈 허용**: 비동기라 다른 화면 이동해도 진행됨 → 완료 시 알림/뱃지.
