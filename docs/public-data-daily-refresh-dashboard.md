# 공공데이터 수집 현황 대시보드

## 목적

`/public-data/daily-refresh` 화면은 GROW-GATE Local EX가 수집한 공공데이터의 상태를 심사위원과 운영자가 바로 확인할 수 있게 보여준다. 이 화면은 수집 성공을 과장하지 않고, 실시간 수집, 저장 데이터 사용, 예비 데이터, 확인 필요 상태를 분리해서 표시한다.

## 주요 개선 사항

- 화면 제목을 `공공데이터 수집 현황`으로 정리했다.
- summary card는 연결 기관, 수집 데이터, 총 수집 건수, 정상 확인, 저장 데이터, 확인 필요를 중심으로 보여준다.
- provider key는 기본 화면에서 숨기고, 기관명과 데이터명을 우선 표시한다.
- raw response hash, schema raw status, provider key는 `상세 보기` 안에서 확인한다.
- `날짜별 수집 결과`는 `최근 수집 실행 이력`으로 바꾸고 최근 2회 실행을 비교한다.
- 실패 사유는 `API_KEY_NOT_CONFIGURED` 같은 개발자 용어 대신 `API 키 설정 필요`처럼 쉬운 말로 그룹화한다.

## 데이터명 표시 원칙

기본 화면은 사용자가 읽을 수 있는 데이터명을 표시한다.

- `BIZINFO_SUPPORT` → `기업마당 지원사업`
- `KIPRIS_FTO` → `KIPRIS FTO 특허 정보`
- `KOTRA_MARKET` → `KOTRA 해외시장 정보`
- `SAFETY_RECALL` → `제품안전 국내 리콜 정보`
- `KCS_TARIFF_LOGISTICS` → `관세·통관·물류 참고 정보`

개발자용 provider key는 상세 영역에만 표시한다.

## 최근 수집 실행 이력

최근 2회 수집 실행을 기준으로 다음 정보를 보여준다.

- `수집일`
- `수집 대상`
- `성공`: `실시간 수집 N건`
- `저장 데이터`: `저장 데이터 사용 N건`
- `실패`: `확인 필요 N건`
- `외부 데이터`: `외부 보조 데이터 N건`
- `진단 반영`: `진단 반영 가능`, `일부 확인 필요`, `진단 반영 제한`
- `상세`: 대표 데이터 5개와 `+ N개 더보기`

좁은 화면에서는 표를 카드형 레이아웃으로 전환해 컬럼 제목과 날짜가 세로로 깨지지 않게 한다.

## 실패 사유 그룹화

실패 사유는 provider별 긴 문자열이 아니라 원인별 카드로 표시한다.

| 원본 코드 | 화면 표시 |
| --- | --- |
| `API_KEY_NOT_CONFIGURED` | API 키 설정 필요 |
| `ENDPOINT_NOT_CONFIGURED` | 공식 호출 주소 확인 필요 |
| `TIMEOUT` | 응답 시간 초과 |
| `SCHEMA_VALIDATION_FAILED` | 데이터 형식 확인 필요 |
| `EMPTY_RESPONSE` | 응답 데이터 없음 |
| `NETWORK_ERROR` | 네트워크 연결 오류 |
| `UNKNOWN_ERROR` | 알 수 없는 오류 |

각 실패 카드에는 영향받은 데이터명, 진단 영향도, 이유, 다음 조치를 함께 표시한다.

## QA 체크리스트

- `최근 수집 실행 이력`에서 날짜와 컬럼 헤더가 세로로 쪼개지지 않는다.
- provider 코드 목록이 기본 화면에 길게 노출되지 않는다.
- `+ N개 더보기`로 긴 데이터 목록을 펼쳐볼 수 있다.
- 실패 사유는 쉬운 우리말로 원인별 그룹화된다.
- 실시간 수집, 저장 데이터, 예비 데이터, 확인 필요 상태가 구분된다.
- raw hash와 provider key는 상세 보기 안에서만 보인다.

## 심사위원 설명 문장

GROW-GATE Local EX는 공공데이터 수집 상태를 숨기지 않고 실시간 수집, 저장 데이터, 예비 데이터, 확인 필요로 나누어 보여줍니다. 심사위원은 어떤 기관의 어떤 데이터가 진단에 활용 가능한지, 최근 수집에서 무엇이 개선되었는지, API 키나 호출 주소 같은 보완 사항이 무엇인지 한 화면에서 확인할 수 있습니다.
