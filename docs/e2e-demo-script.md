## 1. 한 줄 소개

GROW-GATE Local EX는 지역 제조기업이 해외 바이어 문의를 받았을 때, 견적 확정 전에 시장성, 규제·인증, 리콜, FTO/특허, 지원사업, 실행 업무를 공공데이터 근거와 함께 점검하는 rule-based Gate 서비스입니다.

### 제품/기업 정보 입력

"오늘 입력값은 리튬이온 배터리팩, HS 850760, 독일/EU 대상입니다. 바이어는 CE, 배터리 규제, 리콜 이력, 특허 리스크, 납기 가능성, 정부 지원사업을 한 번에 알고 싶어합니다."

"점수와 Gate 상태를 먼저 보고, 바로 아래에서 live/cache/fallback 개수를 확인합니다. fallback은 좋은 근거가 아니라 재확인 대상입니다."

"시장성 점수는 진출 우선순위를 정하는 첫 신호입니다. 높다고 바로 수출 가능하다는 뜻은 아니고, 다음 규제·인증과 FTO 화면을 함께 봐야 합니다."

## 4. 심사위원에게 보여줘야 할 포인트

- 공공데이터 활용은 S10의 `proofRunId`, `source`, `schemaValidation`, `rawResponseSha256`, `live/cache/fallback` 구분으로 설명합니다.
- AI Agent 활용은 "자율 결정"이 아니라 `source-bound evidence workflow`, `claim verification`, `fallback-aware diagnosis`, `LLM assisted report`로 설명합니다.
- final Gate는 rule score와 risk/fallback 조건으로 결정되며, LLM이 `finalGate`를 바꾸지 않는다고 설명합니다.
- fallback, seed, synthetic 데이터는 숨기지 않고 live 공공 API proof와 구분합니다.
- 리포트는 바이어 대응 초안, 내부 회의, 인증기관·변리사 검토 요청서로 이어지는 업무 산출물입니다.

## 5. 예상 질문과 답변

### AI가 자동으로 수출 가능 여부를 결정하나요?

아닙니다. 최종 Gate는 rule 기반 점수와 risk/fallback 조건으로 결정됩니다. LLM은 근거 설명과 보고서 문장 정리를 보조합니다.

### 공공데이터가 실제로 쓰였다는 증거는 어디서 보나요?

S10 근거 데이터 화면에서 provider별 source type, record 수, raw hash, schema validation, proofRunId를 확인합니다.

### fallback이 있으면 서비스가 실패한 것인가요?

실패로 숨기지 않고 "공식 live 근거 부족" 상태로 드러냅니다. fallback은 점수를 올리는 긍정 근거가 아니라 담당자 재수집 또는 원문 확인 대상입니다.

### 리콜 조회 결과가 없으면 안전한가요?

아닙니다. 리콜 데이터 없음은 조회 범위 내 근거가 없다는 뜻일 수 있습니다. 제품 안전은 시험성적서, 인증, 품질 문서와 함께 확인해야 합니다.

### FTO 화면은 특허 침해 여부를 판정하나요?

아닙니다. 공개 특허와 키워드 기반 사전 위험 신호이며, 최종 판단은 변리사 검토가 필요합니다.

### 지원사업 추천은 신청 가능 확정인가요?

아닙니다. 후보 목록입니다. 원문 공고, 신청 조건, 마감일, 제출서류를 별도로 확인해야 합니다.
